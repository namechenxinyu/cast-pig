# 投屏猪 (Cast Pig)

把电脑屏幕或视频文件投屏到局域网内的电视 / 投影仪。绿色单文件应用，
Linux / Windows 双平台，打开即用。

```
版本: 1.5.3    协议: DLNA/UPnP AVTransport    画质: 1080p30 CRF自适应 / 可选720p    延迟: ~2-4s
```

## 快速开始

| 平台 | 做法 |
|---|---|
| Linux | 双击 `启动投屏猪.sh`（或桌面图标） |
| Windows | 双击 `启动投屏猪.bat`；首次缺 ffmpeg 会提示自动下载 |

打开后自动扫描设备；上次用过的设备会**自动预选**（多设备时不会投错），
确认后点「▶ 开始投屏」即投。首次使用在列表里选一次设备和内容模式即可，
之后每次打开都会自动预选上次的选择。详见 `使用说明.txt`。

> Linux 提示：若从压缩包下载导致脚本丢失执行权限（双击没反应/报错），
> 在终端运行一次 `chmod +x 启动投屏猪.sh` 即可。

依赖只有两样：`Python 3.6+（含 tkinter）` 和 `ffmpeg`（本目录优先，其次 PATH）。

## 架构（v1.4 双引擎 + 五级发现链）

```
┌──────────────────── 设备发现(不依赖任何固定端口/地址) ────────────────────┐
│ ① 候选主机(上次连接IP + MAC定位DHCP新IP) × 常见候选端口快速探测            │
│ ② settings.json 上次完整控制地址直接验证                                 │
│ ③ SSDP 组播搜索                                                         │
│ ④ 全网段常见端口并发扫描                                                 │
│ ⑤ 候选主机全端口(65535)深度扫描兜底 —— 端口改成任意值也能找到(实测11秒)   │
└──────────────────────────────────┬──────────────────────────────────────┘
                                   ↓
┌──────────────────── 推流引擎(自动选择 + 失败自愈) ────────────────────────┐
│  识别为黄龙(型号/端口25826) → HLS 滚动切片引擎                            │
│  识别为乐播等其他设备      → 裸 TS 直播流引擎                             │
│  未识别设备               → 先裸流; 18 秒内不持续拉流则自动切 HLS 重试    │
└──────────────────────────────────────────────────────────────────────────┘
```

### 为什么需要双引擎

不同 DLNA 渲染器对"无限直播流"的接受度不同：

- **乐播（49152）**：接受无长度的裸 TS 直播流（滚动窗口 + 尾部切入 + 恒定码率）。
- **投影仪自带黄龙 DLNA（25826，"视频软件投屏"入口）**：播放前先发 HEAD
  探测；无长度头的流直接放弃，4GB 假长度也只拉一小段就断。**HLS 是它的
  正确打开方式**——播放器按 m3u8 轮询切片，实测连续播放数分钟无断流。

> 实战教训：黄龙的 `SetAVTransportURI` 是同步实现，约 10 秒才响应；
> SOAP 超时必须放到 28 秒，元数据传空字符串最稳（传完整 DIDL 反而不播）。

### 端口/地址会变吗？

会。UPnP 服务端口常为动态分配，DHCP 也可能换 IP。v1.3 的对策：

- **端口变了** → 深度扫描兜底（全 65535 端口 11 秒扫完，找到任何端口上的
  description.xml 即识别）；引擎侧还有裸流→HLS 自动降级兜住"认不出型号"。
- **IP 变了** → 按网卡 MAC 在 ARP 表中定位新 IP；再加上 SSDP 与网段扫描。
- 正常情况走 ① ② 快速路径，秒级完成；只有全变了的极端情况才会走到 ④ ⑤。

### 其他关键实现点

- 服务器必须实现 **HEAD**（几乎所有渲染器播放前都会 HEAD 探测）。
- Linux 抓系统声必须用 `parec > FIFO` + ffmpeg `-f s16le` 读管道——
  ffmpeg 的 `-f pulse` 直采会把编码拖到 2~3fps（时间戳倒跳）。
- 画质编码: HLS 模式 `veryfast + CRF17 自适应(上限15Mbps) + BT.709 色彩标签`;
  裸流模式保持 `CBR 10Mbps`(部分渲染器的断流兼容要求)。
- 「输出画质」可选 720p: 用电脑端 lanczos 缩放替代投影仪内置缩放器,
  适配 720p 原生面板的平价投影(实测 SSIM: 静态 0.996 / 动态 0.97)。

## 平台差异

| 环节 | Linux | Windows |
|---|---|---|
| 抓屏 | ffmpeg x11grab（分辨率自适应） | ffmpeg gdigrab |
| 系统声 | parec → FIFO → s16le | dshow「立体声混音」，无则自动降级纯画面 |

## 自检

无界面环境下验证完整链路（发现 → 投屏 → 停止）：

```bash
python3 cast_pig.py --selftest
```

## 已知限制

- 延迟约 2~4 秒：DLNA 渲染器开播前需自缓冲，已是该通道下限；
  零延迟需求请走 HDMI 或 Miracast（需支持 Wi-Fi Direct 的无线网卡）。
- 电视/投影仪端的 DLNA 服务需要开启：投影仪在「视频软件投屏」等入口，
  电视一般在「多屏互动」设置里。
- 若目标设备的 DLNA 实现又偏离标准，优先改 `needs_hls()` 的判定把该设备
  切到 HLS 模式；HLS 的兼容性明显强于裸流。
